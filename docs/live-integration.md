# 真实模型接入与验证

验证日期：2026-09-18。本轮使用用户在仓库根目录 `.env` 中配置的 TypeSafe 和 DeepSeek 密钥，真实浏览器操作目标为 `apps/realtime-home`。没有修改用户的 `.env`，没有将密钥写入前端、日志或验证报告。

## 启动和配置

在仓库根目录运行：

```sh
pnpm install --frozen-lockfile
pnpm dev
```

页面为 `http://127.0.0.1:5174`，世界 API 为 `http://127.0.0.1:3102`。

两个应用共同使用 `@realtime-agent/config`，配置优先级是进程环境变量、应用目录 `.env`、仓库根目录 `.env`。支持 `SYSTEM_ONE_BASE_URL`、`SYSTEM_ONE_MODEL`、`SYSTEM_ONE_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`；旧的 TypeSafe 变量名仍兼容。更高优先级的空密钥会遮蔽根配置。

配置 System One 密钥且未显式设置 `AGENT_MODE` 时，应用默认进入 `live`。无密钥时默认 `demo`；`AGENT_MODE=demo pnpm dev` 可在有密钥的情况下运行离线演示。显式 `live` 缺少密钥会拒绝启动，真实请求失败不会切换为规则模拟。

本次使用的请求模型为 `jev-latest` 和 `deepseek-flash`，实际成功响应中的模型名分别为 `jev-1.13.0` 和 `deepseek-flash`。

## 联调中修复的问题

原启动方式只读取应用目录环境文件，并且不识别用户配置的 `SYSTEM_ONE_*`。已抽出共享服务端配置包，同时接入 home 和 demo；无需复制密钥到两个应用。

模型基址现在统一处理根地址、版本化基址和完整接口路径。DeepSeek 官方端点采用 `max_tokens`、JSON 输出与 `thinking: { type: "disabled" }`，其他 Chat Completions 兼容端点保留 `max_completion_tokens`。这里的慢系统指对话和规划职责，不要求模型开启内部长推理。

真实测试发现，旧快系统提示词会对开放问题反复选择等待而不请求 LLM。已明确：Jev 只能输出行为及数值判断，新的文字回复只能通过 LLM 产生。仍然由 Jev 决定是否调用慢系统、是否采纳建议。本轮当时保留的固定动作置信度门槛已在后续 [自主行为修复](runtime-cadence.md) 中移除，中断判断仍保留。

进一步复跑发现，正常对话的无记忆建议返回值曾触发 `memories:invalid_type`。已明确 JSON 示例，并将缺失或 `null` 的可选建议数组解释为空数组；实际动作 ID、非空记忆结构和必须的回复文本仍严格校验。错误诊断只记录固定字段名和校验代码，不输出原始模型响应或内部推理。

成功响应会记录 HTTP 状态、返回模型名、时间、token 用量，以及提供商返回的请求 ID。思考面板新增“最近成功的模型响应”，同一份元数据也可在运行记录中导出。
