# 桌面任务启动与执行闭环修正

2026-09-20。对应用户反馈：输入任务并点击开始，页面看不到任务执行。

## 发现并修正的可复现问题

1. **无计划时可执行候选为空。** 旧桌面策略同时询问 body/action、think、review 与 channel；body 只有 wait，是否请求规划依赖另一个概率阈值。存在一直选择等待、不请求 LLM 的路径。新 `DesktopDecisionPolicy` 使用一个 `next_step` Choice：请求规划、采纳/退回计划、执行一个绑定操作、重新规划或报告受阻。只有真正有请求在途时由运行时继续等待。
2. **真实控件名称会超出版本字段限制。** 原先将可访问性名称和几何信息串接为实体版本；长控件名称可能超过核心版本字段长度上限，使观察入库失败。现在使用固定长度 SHA-256 版本，原始内容仍保留在观察中。
3. **失去观察会留下 active + paused。** 现在任务明确变为待处理并显示原因。重新连接后不会把旧任务冒充为仍在执行；重新提交才恢复。
4. **停滞、拒绝与调用错误不可见。** 新增任务阶段和原因；无动作决策、连续拒绝及任务等待均有界。HTTP/解析/模型期限错误显示在任务附近，不会继续无声消耗调用预算。
5. **页面将状态更新串在截图之后。** 现在状态定期读取，截图单独保持一个在途请求。提交有独立锁；无模型、无所选窗口或输入未结算时显示明确条件；错误不会被下一次成功轮询清空。
6. **决策期间观察老化。** 分发前重新读取真实窗口，同时校验旧绑定的窗口/布局，避免将旧坐标直接套到新现场。手动帧也绑定控件布局。操作完成后，页面只接受更新于该回执的画面，避免“任务完成”旁仍显示操作前截图。

`desktop-decision.ts` 只投影所选应用和有界控件文字。其他打开的窗口标题、整份运行时和重复历史不随桌面决策发给模型。LLM 的实际计划以明确字段给 Jev 检查，接受计划不会自动执行整条队列。

## 验证入口

普通回归使用网络响应/设备夹具，包含实际 SDK 请求和响应解析，不再只以固定 `think=true` 的本地策略替代自动链路。

```powershell
pnpm --filter @realtime-agent/computer typecheck
pnpm --filter @realtime-agent/computer test
pnpm --filter @realtime-agent/computer test:native
```

新增 `tests/native/desktop-task.test.ts`：通过网页开始任务，走实际 SDK 协议与原生 Windows 驱动，核对独立测试窗口的真实文字。它的模型响应仍为夹具，报告明确标识 `modelTransport: response-fixture`。

显式真实模型验收：

```powershell
pnpm test:computer:live
```

该命令使用当前模型配置、网页按钮和自建原生窗口；调用上限 12 次、总期限 60 秒，不操作用户已有工作窗口。结果保存在 `apps/realtime-computer/test-results/desktop-task/live-verification.json`，截图为 `live-completed.png` 与 `live-native-result.png`。真实请求记录仅包含阶段、HTTP 状态和时长，不打印凭据。

本轮验收结果：

健康接口新增 `decisionProtocol: desktop-choice-v1`，可用于判断当前端口是否仍是旧服务。源码更改后需要重启 Computer；现有普通 `tsx` 进程不会自行加载新协调逻辑。

一项原生窗口任务通过，不等于跨应用任务、所有控件或长期成功率已验收。当前操作仍绑定所选窗口；默认“整个桌面”只提供观察，开始任务前必须选择目标应用。应用启动时会读取配置，但只有提交任务后才调用模型。
